# Плата Сергея (yasminalia) + наше лицо

Исходник инженера: https://github.com/sergey2a/yasminalia — один файл `main.c`, 525 строк.

## Что у него использовано

| Слой | Чем сделано |
|---|---|
| Фреймворк | Arduino, ESP32-S3 N16R8 |
| Экран | `Adafruit_GFX` + `Adafruit_ST7789`, 240×320, SPI 20 МГц, текст латиницей (`toDisplayable()` выкидывает кириллицу) |
| Микрофон | INMP441, legacy `driver/i2s.h`, I2S0, 16 кГц, 32 бита |
| Динамик | MAX98357, I2S1, 16 бит моно |
| Кнопка | сенсор TTP223 на GPIO4, касание = HIGH |
| Сеть | `WiFi` + `HTTPClient` + `WiFiClientSecure` (`setInsecure()`) |
| Сервер | `POST https://tatarser.213-109-202-195.sslip.io/v1/dialog/audio`, multipart: `audio`, `session_id`, `speaker=alsu`, `output_format=wav` |
| Ответ | либо голый WAV, либо JSON: `session_id`, `transcript`, `reply_text`, `audio_base64` (`ArduinoJson`) |

## Распиновка — его, код — наш

Провода уже впаяны, поэтому пины взяты из его прошивки один в один
(`include/config.h`, ветка `BOARD_S3_YASMINA`):

```
дисплей  SCLK 9   MOSI 8   CS 10   DC 11   RST 12   BLK → 3V3
микрофон SCK  5   WS   6   SD  7          (I2S0)
динамик  BCLK 15  LRC  16  DIN 17         (I2S1)
кнопка   TOUCH 4
```

`PIN_MISO` = 18 — к дисплею не идёт, это свободный пин-заглушка: `SPI.begin()`
при `miso = -1` сам подставляет штатный пин шины и делает ему `pinMode(INPUT)`,
а штатный для FSPI — GPIO13. Подробнее в комментарии в `config.h`.

## Чем наш код отличается от его — и почему полосы

1. **Драйвер экрана.** У него `Adafruit_ST7789` на 20 МГц. У нас круглый
   GC9A01 со своей таблицей инициализации (`src/gc9a01.cpp`): чужая таблица
   ST7789 частично «подходит» — панель заводится, но гамма, инверсия и
   развёртка не те, отсюда полосы и рябь. Плюс у нас инициализация всегда идёт
   на 10 МГц и только пиксели — на 40 МГц: сбой на пикселях даёт рябь одного
   кадра, а сбой на таблице — мёртвый экран, который «иногда заводится».
2. **Чтение микрофона.** Он читал по одному 32-битному слову за вызов
   `i2s_read`. Вызов стоит дороже самого чтения — на длинной реплике сэмплы
   теряются и речь уезжает по темпу. У нас пачки по 256 сэмплов.
3. **Смена частоты на воспроизведении.** Он переустанавливал драйвер I2S
   (`i2s_driver_uninstall` + `install`) — это роняет DMA и щёлкает в динамик.
   У нас `i2s_set_clk`.
4. **Тело ответа.** Он клал его в `String` (`http.getString()`) — то есть в
   внутреннюю кучу, где нескольких сотен килобайт WAV просто нет. У нас ответ
   стримится в PSRAM, а JSON разбирается zero-copy прямо по этому буферу,
   поэтому `audio_base64` не копируется второй раз.
5. **Лицо не замирает.** У него всё в одном `loop()`, и на время запроса
   экран стоит. У нас лицо — отдельная задача на ядре 0, голос — в `loop()`
   на ядре 1.

## Сценарий

```
обычное лицо  ──зажал кнопку──▶  FACE_LISTEN (пишем, пока держат)
     ▲                                  │ отпустил
     │                                  ▼
     │                        FACE_IDLE + setThinking(true)
     │                        взгляд уходит вверх и плывёт, пока ждём сервер
     │                                  │ ответ
     │                                  ▼
     └────────────  эмоция ответа + setSpeaking(true), рот по громкости WAV
```

Эмоцию берём из поля `emotion` (или `mood`) в JSON, если сервер его шлёт.
Старый сервер его не шлёт — тогда угадываем по `reply_text` словарём в
`src/voice.cpp` (`KEYS`): любовь, радость, шалость, удивление, грусть,
прощание. Не угадали — нейтральное говорящее лицо `FACE_SPEAK`.

## Сборка

```sh
cp include/secrets.h.example include/secrets.h   # вписать Wi-Fi
pio run -e yasmina -t upload
pio device monitor -e yasmina
```

В мониторе порта работают и ручные команды: `1`..`9` — эмоция, `t` — речь.
