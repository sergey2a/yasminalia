# Ясмина — лицо на дисплее GC9A01

Вывод лица умной колонки на круглый дисплей 240×240 (GC9A01, SPI).
Черты лица — наши собственные кривые Безье, без готовых библиотек лиц
и без растровых картинок в памяти. Девять выражений, у каждого своя палитра
и своё украшение: сердечки, месяц, слезинка, искры.

## Что внутри

| Файл | Зачем |
|---|---|

| `src/gc9a01.*` | минимальный драйвер панели: инициализация, окно вывода, поток пикселей |
| `src/main.cpp` | задача лица на одном ядре, голосовой цикл на другом |
| `src/voice.*` | микрофон, кнопка, запрос к серверу диалога, воспроизведение ответа |
| `include/config.h` | пины, частота SPI, границы живой полосы экрана |
| `tools/shapes.py` | контуры ⇄ SVG: правка форм в Figma или Inkscape |

## Как это нарисовано

Каждая черта лица — замкнутый контур из шести кубических кривых Безье.
Черт четыре: глаз, бровь, рот и украшение. Плюс второй контур рта —
раскрытый, для речи.
Кадр собирается в три прохода, как в растеризаторах шрифтов:

1. контуры разбиваются на отрезки и заливаются по строкам в **маску покрытия**
   (8 бит на пиксель, 4 подстроки на строку — отсюда сглаженный край);
2. маска уменьшается вдвое и дважды размывается box-фильтром — это **ореол**;
3. маска и ореол смешиваются с фоном и уходят в панель полосами.

Честное поле расстояний до кривой Безье на каждый пиксель стоило бы 70–90 мс
на кадр — поэтому заливка по строкам и размытие маски вместо него.
Заливка и ореол занимают несколько миллисекунд, основное время кадра забирает
SPI: полоса лица 140 строк на 40 МГц — это 13.4 мс.

Пропорции сняты промерами с эталонного рендера колонки
(`assets/Pasted image.png`), приведёнными к панели 240×240: глаза шириной 45 px
на ±52 от оси, заливка `RGB(254,225,164)`, ореол `RGB(255,126,15)`.

## Как менять внешность

Числа лежат в `src/shapes.cpp` — по контуру на черту и состояние, между
маркерами `// >>> eye_happy` и `// <<< eye_happy`. Узлы контура:

```
        n1  вершина
    n0          n2      n0, n2 — края
      n5      n3        n3, n5 — нижние углы
        n4              n4 — середина нижней кромки
```

Если `n4` ниже углов — глаз открытый; если выше — получается прищур-полумесяц.
На этом и построен переход `idle → happy`, и точно так же раскрывается рот.

Кроме контуров в состоянии лежат:

* **цвета** — `ink` (черты), `decorInk` (украшение), `glowInk` (ореол).
  Они интерполируются наравне с координатами, поэтому переход из тёплого
  `idle` в розовый `love` — плавная заливка, а не подмена палитры;
* **`wink`** — 0 или 1. Прикрывает только правый глаз, так что асимметрия
  делается одним числом, без второго контура;
* **`decorOn`** и **`decorMirror`** — видно ли украшение и рисовать ли его
  парой. Несимметричную фигуру по центру (месяц) зеркалить нельзя: получатся
  две половинки, развёрнутые друг к другу.

Править можно в редакторе кривых:

```bash
tools/shapes.py export preview-out     # -> shapes_idle.svg, shapes_happy.svg, ...
# правишь shapes_happy.svg в Figma или Inkscape
tools/shapes.py import preview-out/shapes_happy.svg happy
tools/preview/build.sh                 # смотришь результат
```

Рисуется **правая половина лица**, левая зеркалится прошивкой. В SVG правь
только контуры с id `eye`, `brow`, `mouth`, `mouth_talk` и `decor`;
полупрозрачная левая половина — подсказка, при импорте она игнорируется.

Одно требование: **у одной черты во всех состояниях должно быть ровно шесть
сегментов в одинаковом порядке.** Морфинг между состояниями — это интерполяция
координат, поэтому число точек обязано совпадать. Импорт проверяет это сам.

## Подключение

| GC9A01 | S3 DevKitC-1 N16R8 | S3 supermini | ESP32 WROOM |
|---|---|---|---|
| SCL/SCK | GPIO12 | GPIO4 | GPIO18 |
| SDA/MOSI | GPIO11 | GPIO6 | GPIO23 |
| CS | GPIO10 | GPIO7 | GPIO5 |
| DC | GPIO13 | GPIO5 | GPIO2 |
| RST | GPIO14 | GPIO8 | GPIO4 |
| BL | GPIO21 | GPIO9 | GPIO15 |
| VCC | 3.3 В | 3.3 В | 3.3 В |
| GND | GND | GND | GND |

Пины меняются в `include/config.h`. MISO к дисплею не идёт, но `PIN_MISO` там
задан не просто так — почему, написано в
[правилах работы с платой](docs/board-esp32-s3-n16r8.md).

**Проверено на живой плате:** S3-DevKitC-1 N16R8, шина 80 МГц, 50 FPS.
Прежде чем перепаивать что-либо, прочитай документ по ссылке — две из трёх
проблем при запуске оказались не в схеме, а в коде и настройках сборки.

## Сборка

```bash
pio run -e s3n16r8 -t upload     # плата, на которой всё проверено
pio run -e s3super -t upload     # плата под серийную сборку
pio run -e wroom   -t upload     # классический ESP32
pio run -e paneltest -t upload   # тест самой панели, лицо не рисуется
pio device monitor -e s3n16r8    # цифры 1..9 — эмоция, t — говорение
```

Занято: 95 КБ RAM и 312 КБ флеша. Из памяти 66 КБ — буферы кадра: маска
240×140, битовая карта украшения, ореол в половинном разрешении и полоса
вывода. Кадр считается за 26 мс, из них 15.6 мс — выгрузка по SPI.

Arduino Nano для этой задачи не годится: одна только маска покрытия больше
всей его памяти.

## Голос

Среда `yasmina` — это лицо плюс диалог на спаянной плате: микрофон INMP441,
усилитель MAX98357, сенсорная кнопка. Распиновка взята из платы инженера
(`BOARD_S3_YASMINA` в `config.h`), программная часть — наша; чем именно она
отличается от его прошивки и откуда брались полосы на экране, разобрано в
[docs/yasminalia-integration.md](docs/yasminalia-integration.md).

```
обычное лицо  ──зажал кнопку──▶  FACE_LISTEN, пишем пока держат
     ▲                                  │ отпустил
     │                        FACE_IDLE + setThinking(true):
     │                        взгляд уходит вверх и плывёт, пока ждём сервер
     │                                  │ ответ
     └────────────  эмоция ответа + setSpeaking(true), рот идёт по громкости WAV
```

Эмоция берётся из поля `emotion` (или `mood`) ответа сервера; если сервер его
не шлёт — угадывается по `reply_text` словарём в `src/voice.cpp`.

Лицо крутится **отдельной задачей на ядре 0**, голос — в `loop()` на ядре 1.
Иначе оно замирает ровно на тех секундах, пока идёт запрос, — то есть когда
Ясмина «думает» и смотреть на неё интереснее всего.

```bash
cp include/secrets.h.example include/secrets.h   # вписать Wi-Fi
pio run -e yasmina -t upload
```

## Если под рукой только Arduino IDE

```bash
tools/make_arduino_sketch.sh          # -> arduino/Yasmina/
```

Скрипт раскладывает те же исходники так, как их хочет Arduino IDE: всё одним
слоем, `main.cpp` становится `Yasmina.ino`, а флаги из `platformio.ini` —
файлом `board_select.h`. Настройки платы и единственную нужную библиотеку
(ArduinoJson) перечисляет `arduino/Yasmina/README.txt`.

Папку не правят руками: правки идут в `src/`, потом скрипт прогоняется заново.
Оптимизацию Arduino IDE не даёт задать мышкой, поэтому `face.cpp` просит `-O2`
сам, прагмой в первой строке — иначе `-Os` съедает полтора десятка кадров.

## Как звать из своего кода

```cpp
#include "face.h"

face::setState(FACE_LISTEN);           // начали слушать
face::setState(FACE_SPEAK);            // пошёл ответ
face::setThinking(true);               // ждём сервер: взгляд уходит вверх
face::setSpeechLevel(0.7f);            // не обязательно: вести рот по громкости TTS
face::setState(FACE_HAPPY, true);      // true — без плавного перехода
```

В `loop()` должен как можно чаще вызываться `face::tick()` — он сам ограничивает
себя по частоте кадров. Блокирующих задержек в цикле быть не должно, иначе лицо
замрёт; если голосовая часть будет надолго занимать процессор, вынеси `tick()`
в отдельную задачу FreeRTOS на втором ядре — так и сделано в `src/main.cpp`.

| Состояние | По-татарски | Что это |
|---|---|---|
| `FACE_IDLE` | тынычлык | спокойное ожидание |
| `FACE_LISTEN` | тыңлыйм | слушает: глаза шире, брови подняты |
| `FACE_SPEAK` | сөйлим | нейтральное говорящее лицо |
| `FACE_HAPPY` | шат | радость, глаза полумесяцами |
| `FACE_LOVE` | гашыйк | сердечки вместо глаз, розовая палитра |
| `FACE_WINK` | шаян | подмигивает, рядом искорки |
| `FACE_SURPRISE` | гаҗәп | круглые глаза, брови высоко, рот овалом |
| `FACE_SLEEP` | йокы | глаза сомкнуты, месяц, холодный синий |
| `FACE_SAD` | моң | брови домиком, рот вниз, слезинка |

Моргание, дыхание, блуждающий взгляд и движение рта идут сами.

**Говорение — не эмоция, а отдельная ось.** Ясмина может говорить с любым
выражением лица: рот смешивается между сомкнутым и раскрытым контурами
текущего состояния, всё остальное лицо живёт своей жизнью.

## Превью без прошивки

```bash
tools/preview/build.sh            # результат в preview-out/
```

Собирает настоящий `src/face.cpp` и `src/shapes.cpp` под Linux, подменяя панель
буфером в памяти. Кладёт в `preview-out/` портреты всех состояний,
`preview.gif` с анимацией и SVG-файлы контуров.

## Если что-то не так с картинкой

* **белый или чёрный экран** — проверь RST и DC, они важнее остальных;
* **негатив по цветам** — убери команду `0x21` (инверсия) из `INIT_SEQ`;
* **зеркально или повёрнуто** — подбери `MADCTL` в `config.h`: `0x08`, `0x48`, `0x88`, `0xC8`;
* **полосы и мусор при выводе** — снизь `SPI_HZ` до 27 МГц, длинные провода 40 МГц не держат;
* **мало FPS** — в мониторе печатается профиль стадий кадра, видно, во что упёрлись;
* **подсветка горит, экран пустой** — почти наверняка не схема, а один из разобранных
  случаев в [правилах работы с платой](docs/board-esp32-s3-n16r8.md).
